# SkillOpt 优化器：像训练神经网络一样训练产品经理技能

> 把微软 SkillOpt（Microsoft SkillOpt）的[自进化智能体技能方法论](https://github.com/microsoft/SkillOpt)用到你的产品经理技能上。把任意 SKILL.md 当作可训练的状态，通过 **rollout → reflect → aggregate → select → update → evaluate** 循环迭代改进，编辑动作有界，并以验证关卡把关。

## 这个技能做什么（What This Does）

本技能带你走完 SkillOpt 训练循环，优化任意一份产品经理技能文档。核心洞察：**技能文档就是可训练的文本**——就像神经网络的权重，只不过用自然语言写成。一个独立的优化器检查执行轨迹、提出有界编辑，只在改动能严格提升留出验证集表现时才接受。

### 核心循环（一个 Epoch）

```
Rollout → Reflect → Aggregate → Select → Update → Evaluate
```

| 阶段 | 发生什么 | 产品经理场景示例 |
|-------|-------------|-------------------|
| **Rollout（执行）** | 智能体用当前技能执行任务 | 让技能产出 3 份 PRD / SWOT 分析 / 用户画像 |
| **Reflect（反思）** | 优化器分析轨迹，产出反馈 | 哪些做对了？漏了什么？哪儿跑偏了？ |
| **Aggregate（聚合）** | 合并多条轨迹的反思 | 把 3–5 次执行的洞察归并成清晰模式 |
| **Select（选择）** | 提出有界编辑操作 | 加一条检查项 / 删含糊指令 / 换掉弱示例 |
| **Update（更新）** | 编辑**只有在严格提升**留出集得分时才被接受 | 跑验证任务 → 对比改动前后的质量分 |
| **Evaluate（评估）** | 按验证关卡测最终表现 | 最终得分报告：这个 Epoch 真的让技能变好了吗？ |

## 何时使用（When to Use）

出现以下诉求时触发：
- 「优化 / 训练 / 改进这个产品经理技能」
- 「在这份技能文档上跑一个训练 Epoch」
- 「让这份 SKILL.md 更有效」
- 「通过迭代打磨让这个技能自我进化」
- 「基于真实使用数据系统性地改进技能」
- 「验证某个技能改动是否真的有用」

## 如何跑 SkillOpt 训练循环

### 阶段 1：准备（Setup）

1. **确定目标技能**——你想优化哪份 SKILL.md？
2. **定义验证任务**——造 5–10 个该技能应能处理的代表性产品经理任务：
   - **训练集（70%）**：用于反思和生成编辑
   - **验证集 / 留出集（30%）**：用于把关——**编辑过程中绝不可见**
3. **建立基线**——用当前技能跑验证集，给每个结果打分（0.0–1.0）

### 阶段 2：训练 Epoch（Training Epoch）

跑完一个完整 Epoch：

#### 第 1 步：Rollout（执行）
用当前版本的技能文档执行训练集任务。记录**完整轨迹**（不只是结果）：
- 智能体产出了什么？
- 它走了什么推理路径？
- 它在哪儿犹豫或跑偏？

#### 第 2 步：Reflect（反思）
用优化器模型（一次独立的大模型调用）分析每条轨迹：
```markdown
## 反思模板
- **做对了什么**：带来好输出的具体指令
- **做错了什么**：令人困惑、缺失或起反作用的指令
- **根因**：失败为什么发生？（措辞含糊？缺步骤？示例不对？）
- **改进思路**：什么有界编辑能修掉它？
```

#### 第 3 步：Aggregate（聚合）
合并所有训练执行的反思。重点找：
- **反复出现的失败模式**（前 3 个）
- **反复出现的成功模式**（前 3 个）——保护它们，别被编辑误伤
- **缺口**——技能本该有却没有的能力

#### 第 4 步：Select（选择有界编辑）
只用以下几种操作，提出 1–3 个**有界编辑**：

| 操作 | 规则 | 示例 |
|-----------|-------|---------|
| **Add（新增）** | ≤50 token；插入新指令/检查项/示例 | 新增：「始终包含明确的『假设』章节」 |
| **Delete（删除）** | 删除 ≤30 token 的无效内容 | 删除：「考虑市场趋势」（太含糊） |
| **Replace（替换）** | 用改进版换掉 ≤60 token | 把含糊指令换成结构化模板 |

**重要：**设定**文本学习率预算**——每个 Epoch 的总改动控制在技能文档的 10% 左右。小而安全的编辑，比大改稿更能复利。

#### 第 5 步：Gate（把关）——用留出集验证
用候选技能跑**留出验证集**（训练中从未用过的任务）：
- 按评分标准给每个输出打分（0.0–1.0）
- 取留出集平均分
- **只有当留出集得分较基线严格提升时，才接受该编辑**
- 若得分下降 → **拒绝**该编辑，并记入**被拒编辑缓冲池**

#### 第 6 步：Evaluate（评估）与报告
```markdown
## Epoch 报告
- **技能**：[名称]
- **Epoch**：[编号]
- **训练集得分**：[改前] → [改后]（±Δ）
- **留出集得分**：[改前] → [改后]（±Δ）
- **被接受的编辑**：[n] 个（列出）
- **被拒绝的编辑**：[n] 个（列出，附原因）
- **关卡结论**：✅ 接受 / ❌ 拒绝
- **被拒编辑缓冲池**：[n] 条失败记录（防止重复提出坏编辑）
```

### 阶段 3：多 Epoch 训练（Multi-Epoch Training）

跑多个 Epoch。每个 Epoch 都从上一个 Epoch 的最优技能出发。

让多 Epoch 训练稳得住的关键机制：

1. **文本学习率预算**——限制每个 Epoch 的改动幅度
2. **被拒编辑缓冲池**——存下失败编辑，阻止它们被再次提出
3. **慢速 / 元更新**——每 3–5 个 Epoch，对技能整体轨迹做一次更宽的「元反思」
4. **单调接受**——永不接受回退；技能只能变好或持平

### 阶段 4：部署（Deploy）

训练收敛后（留出集得分连续 3 个以上 Epoch 走平），优化后的技能产物（`best_SKILL.md`）即可部署。通常在 300–2,000 token 之间。

## 技能迁移（Skill Transfer）

优化后的技能可以迁移到：
- **不同大模型**（GPT、通义千问等），无需重新优化
- **相似的产品经理任务**（如 PRD 技能可部分迁移到功能规格技能）
- **不同执行场景**（直接对话 → 智能体循环），稍作适配即可

## ⚠️ 硬性规则（Hard Rules）

- **验证关卡必须严格：**只有留出集得分严格提升才接受编辑。没有例外。
- **只做有界编辑：**绝不推倒重写。只做小块的增/删/换。
- **被拒编辑缓冲池：**每条被拒提案都要记录，提类似编辑前先查一遍。
- **先基线后动手：**改动之前，必须先建立定量基线。
- **先证据后行动：**应用前，先把留出集得分和精确的改动 diff 给用户看。
- **先备份后覆盖：**覆盖前，务必先存一份 `{skill}.bak`。
