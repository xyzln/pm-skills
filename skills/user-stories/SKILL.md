# 用户故事

按照 3C 原则（卡片、对话、确认）和 INVEST 标准创建用户故事。生成的故事含描述、设计链接和验收标准。

**使用时机：** 撰写用户故事、把功能拆解成故事、创建需求池（待办列表）条目，或定义验收标准。

**参数：**
- `$PRODUCT`：产品或系统名称
- `$FEATURE`：要拆解成故事的新功能
- `$DESIGN`：设计文件链接（Figma、Miro 等）
- `$ASSUMPTIONS`：关键假设或背景

## 分步流程

1. **分析功能** —— 基于提供的设计和背景
2. **识别用户角色** 与不同的用户旅程
3. **应用 3C 框架：**
   - 卡片：简洁的标题和一句话说明
   - 对话：对意图的详细讨论
   - 确认：清晰的验收标准
4. **遵循 INVEST 标准：** 独立的（Independent）、可协商的（Negotiable）、有价值的（Valuable）、可估算的（Estimable）、小的（Small）、可测试的（Testable）
5. **使用大白话** —— 让小学毕业的人也能看懂
6. **链接设计文件** 以便视觉参考
7. **输出用户故事** —— 采用结构化格式

## 故事模板

**标题：**【功能名称】

**描述：** 作为【用户角色】，我想要【操作】，以便【收益】。

**设计：**【设计文件链接】

**验收标准：**
1. 【清晰、可测试的标准】
2. 【可观察的行为】
3. 【系统正确校验】
4. 【边界情况处理】
5. 【性能或无障碍考量】
6. 【集成点】

## 用户故事示例

**标题：** 最近浏览模块

**描述：** 作为网购用户，我想在商品详情页看到"最近浏览"模块，方便重新查看我看过的商品。

**设计：**【Figma 链接】

**验收标准：**
1. 对每个此前至少浏览过 1 件商品的用户，在商品详情页底部展示"最近浏览"模块。
2. 对本次会话中访问的第一个商品详情页，不展示该模块。
3. 当前商品本身不出现在展示的商品中。
4. 该模块展示商品卡片或缩略图，含图片、标题和价格。
5. 每张商品卡片标注浏览时间（例如"5 分钟前浏览过"）。
6. 点击商品卡片后，跳转到对应的商品详情页。

## 输出交付物

- 该功能的一套完整用户故事
- 每个故事含标题、描述、设计链接和 4-6 条验收标准
- 故事相互独立，可按任意顺序开发
- 故事的粒度以一个冲刺周期可完成为宜
- 故事关联相关设计文档
