# SkillOpt-Sleep：PM 技能的离线自我进化

> 给你的 PM 技能装上一个**睡眠周期**。你离开的时候，它回顾过往的 PM 技能使用记录，重跑重复任务，并把学到的东西整合为对技能的**经验证、有门控的**改进。你的技能越用越强，且提升可度量——无需任何提示词工程。

它融合了三个有力的思想：

| 思想 | 贡献 |
|------|-------------|
| **SkillOpt** | 技能文档 = 可训练的文本；增/删/换的有界编辑；**留出门控**只保留真正有用的改动 |
| **AI 助手离线整合** | 回顾过往会话；绝不改动输入；产出经审核后再采纳 |
| **智能体睡眠** | 周期性离线回放，把短期使用转化为长期技能提升 |

## 适用场景

当用户想要以下任何一件事时触发：
- "让我的 PM 技能从我的使用方式中学习"
- "让我的技能越用越好"
- "跑一次睡眠/做梦/离线整合周期"
- "回顾我过往的 PM 技能使用情况并给出改进建议"
- "基于我的工作历史让技能自我进化"
- "安排每晚的技能改进"
- "采纳一个已暂存的技能提案"

## 睡眠周期（六个阶段）

```
采集 → 挖掘 → 回放 → 整合 → 门控 → 暂存 → 采纳
```

### 阶段 1：采集

从 AI 助手会话或 `memory/` 目录中读取用户的**过往 PM 技能使用历史**。这一步是**只读**——不改动任何东西。

采集内容：
- `memory/YYYY-MM-DD.md`——每日工作日志（用了哪些技能、做了哪些任务）
- `memory/MEMORY.md`——项目备注与约定
- 任何可用的会话转录或技能调用记录

**产出：** 会话摘要——关于调用了哪些技能、表现如何的结构化总结。

### 阶段 2：挖掘

从采集到的会话摘要中，识别**重复任务**、**使用模式**和**痛点**：

```markdown
## 挖掘结果
- **最常用技能**: [create-prd: 12 次, swot-analysis: 8 次, user-stories: 6 次]
- **重复任务类型**: [为移动功能写 PRD, 为 SaaS 工具做竞品分析]
- **识别到的痛点**: [PRD 总是漏掉成功指标, SWOT 缺乏可执行建议]
- **检测到的用户偏好**: [偏好定量数据而非定性, 喜欢简洁的要点格式]
- **新任务类型**: [用户会做、但现有技能覆盖不好的任务]
```

### 阶段 3：回放

使用相关 PM 技能的**当前**版本，**离线**重跑这些重复任务：

1. 从挖掘出的模式中挑选 3-5 个代表性任务
2. 用当前技能跑每个任务
3. 按评分细则给每个结果打分（0.0-1.0）：
   - **完整性**：是否覆盖了所有必要方面？
   - **准确性**：输出是否正确、相关？
   - **可执行性**：用户能照着输出行动吗？
   - **易用性**：输出结构是否清晰、好读？

**产出：** 当前技能版本的基线分数。

### 阶段 4：整合

这是核心优化步骤：

1. **反思**——分析回放轨迹。哪里出了问题？哪里成功了？
2. **提出有界编辑**——为每个技能提出 1-3 处小的、有针对性的修改：
   - **增**：插入新指令（如"始终包含'成功指标'一节"）
   - **删**：移除无效指令（如删掉含糊的"考虑用户需求"）
   - **换**：把弱内容替换成更强的替代表述
3. **在留出任务上门控**——用一组独立的任务（反思时从未见过）验证每一处编辑
4. **只有严格提升才接受**——留出任务分数必须上升；持平或下降 = 拒绝

**被拒编辑缓冲区：** 记录每一条被拒提案及其失败模式，未来周期提出类似编辑前先查一遍。

### 阶段 5：暂存

把提议的技能改进写入暂存区：

```
.skillopt-staging/{date}/
├── proposed_SKILL.md        # 新的技能内容
├── diff.md                  # 改了什么（前后对比）
├── scores.md                # 留出基线 → 候选分数
├── report.md                # 完整睡眠周期报告
└── backup/                  # 上一版本备份
```

**此刻生效中的技能不会有任何变化。** 提案暂存待用户审核。

### 阶段 6：采纳

用户审核暂存的提案并决定：
- `/sleep adopt` → 应用改动（自动备份上一版本）
- `/sleep reject` → 丢弃提案
- `/sleep modify` → 手动调整后再采纳

## 如何驱动

### 按需睡眠周期

```
用户："对我的 PM 技能跑一次睡眠周期"
助手："正在启动 SkillOpt-Sleep 周期……

第 1 步：从你的工作日志采集 PM 技能使用记录……
  → 在 5 个会话中发现 23 次技能调用
  → 高频技能：create-prd（8 次）、swot-analysis（5 次）、user-stories（4 次）

第 2 步：挖掘重复模式……
  → 识别出 3 类重复任务
  → 在 PRD 技能中发现 2 个痛点

第 3 步：离线回放任务……
  → 基线分数：PRD 0.65，SWOT 0.72

第 4 步：整合改进……
  → 为 create-prd 提出 2 处有界编辑
  → 留出门控：0.65 → 0.82 ✓ 已接受

第 5 步：暂存提案……
  → 暂存至 .skillopt-staging/2026-06-12/

第 6 步：待审核！
  → 运行 `/sleep view` 查看提议的改动
  → 运行 `/sleep adopt` 应用改动
```

### `/sleep` 命令

| 命令 | 动作 |
|---------|--------|
| `/sleep run` | 完整周期：采集 → 挖掘 → 回放 → 整合 → 门控 → 暂存 |
| `/sleep dry-run` | 安全预览：会学到什么，不暂存任何改动 |
| `/sleep status` | 展示历史睡眠周期 + 最新暂存提案 |
| `/sleep view` | 展示最新暂存提案（差异、分数、报告） |
| `/sleep adopt` | 将暂存提案应用到技能（带备份） |
| `/sleep reject` | 丢弃暂存提案 |
| `/sleep schedule` | 设置周期性夜间睡眠周期 |

### 定时夜间周期

为了持续自我改进，睡眠周期可以定时运行：

```
/sleep schedule
  → 建议：每晚凌晨 2 点
  → 创建运行睡眠周期的定时任务/自动化
  → 你早上审核并采纳
```

## 验证证明

为了证明 SkillOpt-Sleep 确实能改进技能：

```markdown
## 留出分数变化

| 周期 | 技能 | 基线 | 候选 | 门控 | 是否接受 |
|-------|-------|:--------:|:---------:|:----:|:---------:|
| 1 | create-prd | 0.65 | 0.82 | ⬆ +0.17 | ✅ |
| 2 | create-prd | 0.82 | 0.88 | ⬆ +0.06 | ✅ |
| 3 | create-prd | 0.88 | 0.85 | ⬇ -0.03 | ❌（已拒绝） |
| 1 | swot-analysis | 0.72 | 0.79 | ⬆ +0.07 | ✅ |
```

门控保证**单调提升**：技能只会变好或保持不变，永不退化。

## 安全规则

- **只读采集**：会话日志只读，绝不修改
- **只暂存，不自动应用**：提案永远等待用户审核
- **采纳前备份**：每次采纳都会为上一版技能创建 `.bak` 备份
- **token/任务预算**：每周期回放不超过 10 个任务、生成不超过 5 处编辑
- **不碰秘密**：会话摘要中的个人身份信息一律脱敏
- **先证据后采纳**：始终展示留出分数和确切的提议差异
