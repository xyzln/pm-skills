# 测试场景

从用户故事创建全面的测试场景，包含测试目标、起始条件、用户角色、分步测试操作与预期结果。

**适用场景：** 编写 QA 测试用例、制定测试计划、定义验收测试场景，或验证用户故事的实现。

**参数：**
- `$PRODUCT`：产品或系统名称
- `$USER_STORY`：待测试的用户故事（标题与验收标准）
- `$CONTEXT`：额外的测试背景或约束

## 分步流程

1. **评审用户故事**与验收标准
2. **定义测试目标** — 要验证什么具体行为
3. **设定起始条件** — 系统状态、数据准备、配置
4. **识别用户角色** — 谁执行测试操作
5. **创建测试步骤** — 将交互拆解为一步一步的操作
6. **定义预期结果** — 每步之后可观察的结果
7. **考虑边界情况** — 非法输入、边界条件
8. **输出详细测试场景** — 可供 QA 直接执行

## 示例测试场景

**测试场景：** 在商品详情页查看「最近浏览」商品

**测试目标：** 验证「最近浏览」区域展示正常，且不包含当前商品。

**起始条件：**
- 用户已登录，或已开启浏览器历史记录
- 用户在当前会话中已浏览过至少 2 个商品
- 用户当前所在的商品页与此前浏览过的商品不同

**用户角色：** 线上购物者

**测试步骤：**
1. 进入任意商品详情页 → 页面底部应出现「最近浏览」区域，展示此前浏览过的商品
2. 滚动到页面底部 → 「最近浏览」区域可见，内含商品卡片
3. 核对商品缩略图 → 图片、标题与价格均正确展示
4. 检查当前商品 → 当前商品不出现在「最近浏览」列表中
5. 点击某个商品卡片 → 用户跳转到对应的商品详情页

**预期结果：**
- 只有浏览过至少 1 个商品后，「最近浏览」区域才会出现
- 区域展示 4-8 张商品卡片，信息完整
- 当前商品被排除在列表之外
- 每张卡片显示「X 分钟/小时前浏览过」的时间戳
- 点击卡片可跳转到正确的商品详情页
- 性能：区域在 2 秒内加载完成

## 交付物

- 每条验收标准对应的全面测试场景
- 与用户故事意图一致的清晰测试目标
- 详细的分步测试操作
- 每步之后可观察的预期结果
- 覆盖边界情况与异常场景
- 可供 QA 团队直接执行并归档
