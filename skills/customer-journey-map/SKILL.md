## 客户旅程地图（Customer Journey Map）

梳理从认知到推荐的端到端客户体验，识别每个阶段的情绪、痛点和改进机会。

### 背景

你正在为 **{user_input}** 制作客户旅程地图。

如果用户提供了文件（访谈记录、问卷数据、分析数据、客服工单或现有旅程地图），先读这些文件。如果提供了网址，用联网搜索了解产品。

### 操作说明

1. **定义用户画像**：走这段旅程的是谁？用一个带待办任务（JTBD）的具体画像，而不是泛泛的「用户」。

2. **梳理旅程阶段**（根据产品调整）：

   | 阶段 | 描述 |
   |---|---|
   | **认知（Awareness）** | 他们从哪里第一次听说产品？ |
   | **考虑（Consideration）** | 他们评估什么？对比哪些替代品？ |
   | **获客（Acquisition）** | 他们如何注册或购买？ |
   | **新手引导（Onboarding）** | 与产品的初次接触——价值实现时间 |
   | **持续使用（Engagement）** | 规律性使用——习惯养成 |
   | **留存（Retention）** | 什么让他们持续回来？什么可能导致流失？ |
   | **推荐（Advocacy）** | 他们什么时候、为什么向别人推荐产品？ |

3. **每个阶段记录**：

   - **触点**：用户与产品、品牌或团队互动的地方（官网、邮件、App 内、客服、社交媒体）
   - **用户行为**：他们在这个阶段做什么
   - **想法与疑问**：他们脑子里在想什么（「这值得我花时间吗？」「怎么操作……？」）
   - **情绪**：他们的感受（兴奋、困惑、沮丧、惊喜）——用评分或表情符号标注
   - **痛点**：摩擦、困惑、流失风险
   - **机会**：如何在这一点上改善体验

4. **识别关键时刻**：
   - **顿悟时刻（Aha moment）**：用户第一次体验到核心价值
   - **真相时刻（Moments of truth）**：他们选择坚持或放弃的决策点
   - **流失诱因**：用户最常见的流失位置

5. **生成旅程地图表格**：

   | 阶段 | 触点 | 用户行为 | 情绪 | 痛点 | 机会 |
   |---|---|---|---|---|---|

6. **给出排好优先级的改进建议**：
   - 哪些痛点对转化或留存影响最大？
   - 哪些速效措施能立刻改善体验？
   - 哪些需要更深投入但回报最大？

逐步思考。保存为 Markdown 文档。如果需要可视化旅程地图，建议用户在 Miro、FigJam 或飞书白板等白板工具中创建，以本分析为基础。
