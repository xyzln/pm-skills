## 分析功能请求

对照产品目标，对客户功能请求做分类、评估和排序。

### 背景

你在分析 **{user_input}** 的功能请求。

如果用户提供了文件（包含功能请求的表格、CSV 或文档），直接阅读并分析。如果数据是结构化格式，可以考虑生成一张汇总表。

### 领域背景

永远不要让客户设计方案。优先排 **机会（问题）**，不是排功能。用 **机会评分**（Dan Olsen）评估客户反馈的问题：机会评分 = 重要性 ×（1 − 满意度），归一化到 0-1。完整细节和模板见 `prioritization-frameworks` 技能。

### 操作说明

用户会描述产品目标并提供功能请求。按以下步骤推进：

1. **理解目标：** 确认产品目标和指导排序的期望成果。

2. **把请求归类成主题：** 合并相关请求，给每个主题命名。

3. **评估战略契合度：** 对每个主题，评估它与既定目标的契合程度。

4. **排序出前 3 个功能**，依据：
   - **影响：** 客户价值和受影响用户数
   - **工作量：** 需要的开发和设计资源
   - **风险：** 技术和市场不确定性
   - **战略契合度：** 与产品愿景和目标的匹配

5. **对每个头部功能**，给出：
   - 理由（客户需求、战略契合）
   - 值得考虑的替代方案
   - 高风险假设
   - 如何用最小成本验证这些假设

逐步思考。保存为 markdown 或创建一份结构化输出文档。
